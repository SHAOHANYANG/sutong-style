## Q1 白话化走方案 A 还是方案 B `[已拍板 2026-10-02：方案 A]`

> **决定：走方案 A。** 复刻当初的白话风格，参照 `salvaged_pairs.jsonl`。
> 缺陷 #2（域外输入失效）本轮**不在数据层处理**，转由 Phase 1 的检索和 Phase 2 的 agent 环在推理侧缓解。
> 连带影响：`human_eval.jsonl` 不再卡 T0.0（见 Q2），恢复为 Phase 1 之前交付即可。
> 若后续想改走方案 B，重跑白话化 + 重训一次即可，成本几十块钱加一小时。

以下为决策时的原始记录，保留备查。



**问题**
模型的已知缺陷 #2（域外输入失效）的根因在白话化这一步：LLM 生成的白话仍带着原文的句子骨架，和真人随手写的白话分布不同。模型实际学到的是「从 LLM 白话回升到原文」。

旧语料已灭失，**重建没有"保持兼容"的包袱**，可以直接修根因。两条路：

- **方案 A（保守）**：复刻当初效果，参照 `salvaged_pairs.jsonl` 的白话风格。风险低，但缺陷 #2 原样保留
- **方案 B（治根）**：prompt 里额外要求打散句子边界、加入口语赘余和语气词，让白话更接近真人写法。可能真正解决缺陷 #2，但需要一把尺子验证

方案 B 的尺子：用 `stylometry` 算**生成白话**与 `corpus/human_eval.jsonl` 里**人工白话**的 `style_distance`，越小越接近真实输入分布。

**假设**
拿不到答复就走 **方案 A**，并在 CHANGELOG 记录「缺陷 #2 未处理，留待后续」。

**影响范围**
训练数据的质量上限。走错了要重跑 907 次 LLM 调用（成本不高，几十块钱，但要重训一次模型）。

**倾向**
建议方案 B。重建本来就要花这笔钱，顺手把根因修了比以后再返工划算；而且「我定位到数据分布是根因，并在重建时修掉了它」是个比「我加了个检索」更有分量的叙述。

## Q6 白话化时“一个”能否省略为“个” `[按假设实现，待人工确认]`

**问题**
T0.0 的 20 条预览中，模型会稳定省略语法性“一 + 通用量词”里的“一”。
若把这类表达也当成事实数字，重试无法收敛；但省略前后的可计量事实并未改变。

**假设**
数字保全检查豁免“一 + 个/只/口/把/件/家/间/条/位/张/片”这类语法性数量表达。
带实际单位或规模的数字仍严格校验，例如年份、日期、人数、斤数、州县数；
`万人` 改成 `上万人` 仍判失败。

**影响范围**
仅影响 `scripts/vernacularize.py` 的生成期重试门槛。T0.3 的正式保真指标仍按 SPEC 3.2
独立实现，不复用这里的简化检查。

## Q7 预览轮数与序列相似度口径 `[2026-10-02 按用户补充执行]`

**问题 / 假设**

避免把隐藏重试变成额外迭代。阈值维持已实现的 0.65 / 0.68 / 0.70，改进只针对 prompt

## Q9 请求模型与响应模型不一致 `[2026-10-03 已确认并预注册对照]`

**事实 / 污染范围**
请求 `deepseek-chat` 的留一法 13 次、round1 20 次、round2 20 次，响应标识全部为
`deepseek-flash`。三组实验均“在 deepseek-flash 上得到”，不得引用为 deepseek-chat 的结果。
留一法新 vs 旧均值 0.687855（新 vs 原文 0.750584），两轮预览新 vs 原文均值
0.733518 / 0.736356；此前关于 prompt 或模型能力的解释没有正确模型归属，需撤回该归因。

**原因 / 证据**
[官方更新日志](https://api-docs.deepseek.com/updates/) 记录 2026-04-24 将 deepseek-chat
映射到 V4-Flash 非思考模式；2026-09-10 又更新 Flash 服务。
当前 [模型与价格列表](https://api-docs.deepseek.com/quick_start/pricing/) 为
`deepseek-flash` 和 `deepseek-v4-pro`。2026-10-03T20:14:38Z 同一账户 /models 实测同样
列出这两个标识：微型诊断请求 chat→flash，而 pro→pro，支持别名变化，无账户档位限制的证据。
官方旧新闻页的 Pro 停服计划与当前更新日志不一致；采用更新日志的继续提供公告，并以实际
模型列表和响应确认可调用性，不按过期计划推测。

**假设 / 单变量边界**
新模型默认启用思考（[接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)），
为避免第二个变量，对照显式关闭；旧轮次的非思考模式仅从官方 chat 别名语义推断，无法
回溯验证后台执行细节。SDK 会发送相同 seed，但供应商未提供 seed 生效证明，不能承诺逐次确定性。
旧模型的未知快照不可恢复，新模型同名响应也不等于不可变版本。

**执行 / 停止**
scripts/model_control.py 仅重放 round2 20 条：展开 prompt、范例、原文、名单、采样参数及
逐条 seed 全部核对旧档案；只改请求模型为 deepseek-v4-pro，保留 temperature=0.2。
模型标识不一致是不可重试的整批致命错误；取消未发起项并逐条记录，在途项仍归档。
完成一次对照就停止，等待人工决定；不执行四臂消融，不启动全量。
